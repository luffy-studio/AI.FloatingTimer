# Changelog

## 2026-10-31 - Persistent billing ledger, deferred payments, and snack sales

- Changed session starts and extensions to generate unpaid bills by default; payment is now optional at start, extension, close, and after close.
- Added immutable extension transactions with request IDs, timestamps, previous/updated duration and bill values, idempotent retries, and atomic timer rollback on failed billing writes.
- Added persistent cash/online payment transactions, partial and multiple payments, automatic unpaid/partial/paid status, due calculations, and post-close collection.
- Added persistent snack menu, availability/category management, immutable orders with price snapshots, quantity adjustments, and automatic snack integration into final bills.
- Added `Extensions`, `Payments`, `Snacks`, and `Menu` workbook sheets plus expanded session export columns for cash, online, due, status, end time, and session ID.
- Expanded dashboard billing details with separate gaming, extension, snack, payment, due, extension-history, payment-history, snack-history, payment-entry, and menu-management controls.
- Expanded billing summaries and daily reports with generated bills, actual collected revenue, pending dues, cash/online collections, snack sales, and payment-status counts.
- Added deterministic gaming-versus-snack revenue allocation for collected payments, backend validation for menu synchronization and extension bounds, and made the live dashboard copy expose payment, snack ordering, adjustment, history, post-close collection, and menu configuration controls.
- Added compatibility migration for the existing 12-column expanded `Sessions` worksheet, preserving its comment-backed sessions while upgrading it to the full billing/export schema. This fixes `/api/sessions`, `/api/snacks/menu`, and billing reports returning HTTP 400 on that workbook.
- Added an end-to-end regression test covering deferred billing, custom 34-minute extension pricing, immutable snack pricing, partial payment, post-close payment, duplicate payment idempotency, and workbook persistence. Updated API documentation.

## 2026-10-31 - Dynamic Paradise Gaming pricing and session billing

- Centralized the official PC Pro, PC Lite, PS5, and existing Racing Simulator prices in the backend, including the ₹15 minimum charge and a documented package-aware rule for custom durations.
- Added the server-authoritative bidirectional pricing quote API: duration changes return price, and manual amounts return the longest purchasable duration without exceeding the entered amount.
- Enforced fixed category assignments from the existing PC names: PC 1/2 → PC Pro, PC 3/4 → PC Lite, and PS5 → PS5. The dashboard no longer offers manual PC category selection.
- Preserved original purchase minutes and amount separately from extension minutes and amount. Extensions now support custom minutes or amount, remain idempotent, update the owning timer immediately, and retain pause/resume behavior.
- Expanded workbook exports with purchased time, additional time, purchased amount, additional amount, and total amount while migrating the prior compact worksheet schema safely.
- Updated the dashboard to show the split time/amount values and synchronized custom pricing controls, plus focused tests for official packages, custom durations, inverse amount quotes, fixed assignments, migration, and extension billing.
